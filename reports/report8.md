# Отчет: Символьная синхронизация (timing recovery) для QPSK

## 1. Назначение модуля

Модуль `timing_sync` решает задачу **символьной синхронизации** - определения моментов времени, в которые нужно брать отсчёты принятого сигнала, чтобы получить корректные QPSK-символы. Приёмник и передатчик имеют независимые тактовые генераторы, поэтому границы символов на приёмной стороне «плавают» относительно локальной сетки отсчётов. Без подстройки стробирование попадает не в центр символа, а на края (где велика межсимвольная интерференция), что даёт размытое созвездие.

Модуль реализует классический **детектор ошибки Гарднера** (Gardner timing error detector) с дробной коррекцией фазы стробирования и сглаживанием ошибки IIR-фильтром.

---

## 2. Структура состояния `TimingSync`

```c
typedef struct {
    int L;          // отсчётов на символ (samples per symbol)
    float tau_s;    // текущее дробное смещение стробирования
    float err_avg;  // усреднённая (сглаженная) ошибка детектора
    float alpha;    // коэффициент IIR-фильтра ошибки (0..1)
    float step;     // шаг коррекции tau_s за один символ
} TimingSync;
```

| Поле | Роль |
|------|------|
| `L` | Период символа в отсчётах. В проекте `L = 10`, т.е. на один QPSK-символ приходится 10 комплексных отсчётов. |
| `tau_s` | Накопленное дробное смещение точки стробирования. Хранится в диапазоне (-1, 1); целая часть «переносится» в индекс отсчёта. Это дешёвая замена дробной задержки без интерполятора. |
| `err_avg` | Выход сглаживающего фильтра ошибки. Именно по его знаку принимается решение о направлении коррекции - это защищает от шума детектора. |
| `alpha` | Коэффициент экспоненциального сглаживания. Меньше — устойчивее, но медленнее реакция. Здесь `0.1`. |
| `step` | Величина сдвига `tau_s` за один символ при ненулевой ошибке. Здесь `0.05` отсчёта — плавная подстройка. |

Инициализация:

```c
timing_sync_init(&ts, L, 0.1f, 0.05f);  // L=10, alpha=0.1, step=0.05
```

Состояние `ts` **сохраняется между вызовами** `timing_sync_process` (буфер за буфером), что обеспечивает непрерывность подстройки - приёмник не «перезапускает» синхронизацию на каждом новом блоке данных.

## 3. Согласованный фильтр: `matched_filter`

```c
void matched_filter(const Complex *in, int in_len, int L, Complex *out)
```

Для прямоугольного импульса (каким формируется сигнал в `rectangular()`) согласованный фильтр - это **скользящее среднее по окну `L`**:

```c
for (int n = 0; n < in_len; n++) {
    out[n].I = 0.0f; out[n].Q = 0.0f;
    if (n < L - 1) continue;                 // окно ещё не набрано
    for (int k = 0; k < L; k++) {
        out[n].I += in[n - L + 1 + k].I;
        out[n].Q += in[n - L + 1 + k].Q;
    }
}
```

**Что происходит:** каждый выходной отсчёт — сумма последних `L` входных. Для прямоугольного импульса это даёт треугольный отклик с максимумом в центре символа. Цели:
1. **Максимизация ОСШ** в точке стробирования (согласованный фильтр - оптимален по критерию SNR для белого шума).
2. **Формирование гладкого отклика**, по которому детектор Гарднера может оценить ошибку Timing (резкие фронты давали бы шумную ошибку).

Первые `L−1` выходных отсчётов нулевые - окно ещё не заполнено. Это учитывается стартовым индексом в `timing_sync_process`.

## 4. Детектор ошибки Гарднера: `timing_sync_step`

Функция делает **один шаг** синхронизации: оценивает ошибку по трём соседним отсчётам, корректирует `tau_s`, выдаёт один символ и возвращает следующий индекс.

### 4.1. Выбор трёх отсчётов

```c
int n  = *idx;
int n2 = n - 2;   // «ранний» отсчёт
int n1 = n - 1;   // «средний» — текущая точка стробирования
int n0 = n;       // «поздний» отсчёт
```

Стробирование ведётся по `n−1`. Отсчёты `n−2` и `n` — соседние, отстоящие на один отсчёт в обе стороны. Для `L = 10` они находятся далеко от центра символа, но детектор Гарднера работает именно на такой паре «ранний/поздний» вокруг среднего.

### 4.2. Ошибка Гарднера

```c
float e = x1_i * (x0_i - x2_i) + x1_q * (x0_q - x2_q);
```

Это скалярное произведение среднего отсчёта на разность крайних. Свойства:
- При точном стробировании в центре символа `x0 ≈ x2` (симметрия отклика), поэтому `e ≈ 0`.
- При раннем/позднем стробировании разность `x0 − x2` пропорциональна `sin(2π·τ/T)`, и ошибка меняет знак.
- Работает **независимо от несущей фазы** - это ключевое преимущество детектора Гарднера: его можно применять до carrier recovery.

### 4.3. Сглаживание ошибки

```c
ts->err_avg = (1.0f - ts->alpha) * ts->err_avg + ts->alpha * e;
```

IIR-фильтр первого порядка. Мгновенная ошибка `e` шумная (особенно на краях символа), поэтому решение о коррекции принимается по сглаженному значению. При `alpha = 0.1` постоянная времени ~10 символов - компромисс между устойчивостью и скоростью отслеживания дрейфа.

### 4.4. Коррекция фазы стробирования

```c
if (ts->err_avg > 0.0f)      ts->tau_s += ts->step;
else if (ts->err_avg < 0.0f) ts->tau_s -= ts->step;
```

Знак сглаженной ошибки задаёт направление сдвига. Шаг фиксированный (`0.05` отсчёта за символ) - это простейший вариант; в более продвинутых реализациях шаг пропорционален величине ошибки (пропорционально-интегральный контур).

### 4.5. Перенос целой части в индекс

```c
while (ts->tau_s >=  1.0f) { ts->tau_s -= 1.0f; n += 1; }
while (ts->tau_s <= -1.0f) { ts->tau_s += 1.0f; n -= 1; }
```

`tau_s` хранится в (−1, 1). Когда накопленное дробное смещение переходит через ±1, оно «переносится» в целочисленный индекс `n`. Так реализуется **дробная задержка без интерполяции**: точность ограничена одним отсчётом, но для `L = 10` и медленного дрейфа этого достаточно. Альтернатива - полиномиальный интерполятор (Фарроу/Кубический), но он дороже.

### 4.6. Выход символа и следующий индекс

```c
sym->I = x1_i;
sym->Q = x1_q;
*idx = n + ts->L;
```

Символ берётся из «среднего» отсчёта `x1` (то есть `n−1` на момент входа). Следующая точка стробирования - через `L` отсчётов от скорректированного `n`. Возврат `1` означает «символ выдан».

## 5. Цикл по буферу: `timing_sync_process`

```c
int timing_sync_process(TimingSync *ts, const Complex *in, int in_len,
                        Complex *symbols, int max_sym)
```

1. **Защита от вырожденных входов:**
   ```c
   if (in_len < ts->L || max_sym <= 0) return 0;
   ```

2. **Согласованная фильтрация** всего буфера во временный массив `filtered_signal` (выделяется и освобождается внутри функции — буфер на кадр, не критично).

3. **Стартовый индекс:**
   ```c
   int idx = ts->L + 2;   // чтобы были валидны n-2, n-1, n
   ```
   Нужно, чтобы для первого шага существовали все три отсчёта, и фильтр уже набрал окно.

4. **Основной цикл:**
   ```c
   while (count < max_sym && idx < in_len) {
       int old = idx;
       if (timing_sync_step(ts, filtered_signal, in_len, &idx, &sym))
           symbols[count++] = sym;
       if (idx <= old) idx = old + ts->L;   // защита от зацикливания
   }
   ```
   - Цикл идёт, пока не набрали `max_sym` символов или не дошли до конца буфера.
   - Защита `idx <= old` спасает от ситуации, когда при большом отрицательном `tau_s` индекс уходит назад или «стоит на месте» - иначе возможен бесконечный цикл.

5. **Возврат** числа выданных символов; состояние `ts` остаётся изменённым для следующего вызова.

## 6. Что происходит с сигналом - сводка

```
вход: Complex[] (нормированные I/Q, L отсчётов на символ)
  │
  ├─ matched_filter        → скользящее среднее по L, треугольный отклик,
  │                          максимум в центре символа
  │
  ├─ timing_sync_step      → детектор Гарднера: e = x1·(x0 − x2)
  │                          IIR-сглаживание: err_avg
  │                          коррекция: tau_s ±= step
  │                          перенос целой части в n
  │
  └─ выход: Complex[] символов (по одному на период L)
```

Ключевая идея: **согласованный фильтр даёт гладкий отклик**, а **детектор Гарднера по трём точкам оценивает, в какую сторону сдвинуть стробирование**, чтобы попасть в максимум. Сглаживание и малый шаг обеспечивают устойчивость к шуму, сохранение состояния между буферами - непрерывность слежения за дрейфом тактов.
